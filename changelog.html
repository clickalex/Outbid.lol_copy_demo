What changed, and what did not.

A lightweight changelog for the static site. The daily bot remains responsible for the market-audit data hooks, inventory CSV and stats JSON.

27 Aug 2026

About page grown from a hero into a full guide

Five new sections, same static-by-design rules — no new dependencies, no trackers.

  • New sections: What’s inside (the three layers — research, decision tools, launch kit — with links into each), The story (a five-entry timeline from the 19 Aug trend ignition through the 27 Aug re-scan and audit loop), By the numbers (eight stat cards: live board total via the same runtime-fetch pattern the ideas page uses, with the committed snapshot as the offline fallback), Five rules this project won’t break (static by design, bot-owns-numbers/humans-own-judgements, evidence over vibes, scope-locked launch kit, every change audited) and a colophon (data source and licence, built-with, contact routes).
  • Metadata: JSON-LD Person structured data for the maker; description meta updated to cover the fuller page.
  • Auditor: the JS syntax check now skips non-JavaScript script blocks (application/ld+json and friends) so structured data can be added without false flags.
27 Aug 2026

Board counts are now bot-owned, and Legal joined the nav

Two maintenance changes: every inventory count on the ideas page now refreshes itself, and the site nav covers the Legal checklist everywhere.

  • Bot-owned counts: all 27 hand-written board-count references in ideas.html prose ("0 boards across all 450", "the 450-board inventory", …) were moved into data-stat="ideas-boards-total" spans — 30 bot-patched spans in total. The daily bot rewrites every one of them on each run, so the counts can no longer go stale between bot passes (verified: the bot's own patch functions were applied offline against the committed 450-board snapshot — idempotent, and a simulated total of 500 flipped all 30 spans). The ideas-page bot pass was also re-run to pick up the collision-watch card at 30 watched ideas (was 24 after the six new verticals were added).
  • Nav: the Legal checklist is now in the top nav of all 17 report pages (12-link set: Audit, Ideas, Tools, Search, Picker, Simulator, Checklist, Calculator, Launch, Changelog, About, Legal) — it was only ever linked from its own page and the Tools hub, despite declaring data-page="legal". The mobile bottom quick-bar on about.html was normalized to the same 5-link set every other page ships (it had swapped Search for a self-link).
  • Auditor: scripts/audit_dom.js now also enforces mobile-bottom-nav set equality across pages and requires every body[data-page] to have a matching top-nav link, so an orphaned highlight like Legal's can never ship again.
27 Aug 2026

20-pass audit loop: 5 real bugs fixed, 3 robustness gaps closed, repo audit tool added

A full-repository audit protocol — fix or improve, reset the counter, repeat until 20 consecutive clean passes.

  • New: scripts/audit.py + scripts/audit_dom.js — a one-command audit pass over everything: Python/bash/JS/JSON/CSV/YAML/SVG syntax, HTML tag balance, duplicate ids, internal links and anchors, bot-sentinel integrity, stats↔CSV↔page consistency, jsdom structural + runtime smoke tests of every page, and launch-kit rebuild idempotence. Documented in the README and logged pass-by-pass in docs/audit-log.md.
  • Fixed: launch-kit owner console was invisible — launch/index.html had two elements with id="admin", so the toggle flipped the section while the inner console stayed display:none; legal-checklist.html crashed on load (TypeError in update()) because its feature-matrix checkboxes are not task rows — progress bar, per-group counts and strike-through were dead; a changelog entry never closed its <div>; docs/pay-to-rank-new-ideas.csv row 9 had an unquoted comma (10 fields vs 9); deep links from search.html pointed at idea anchors that did not exist.
  • Fixed: stale launch/data.js rebuilt from the current 450-board inventory (it still carried the 449-row snapshot).
  • Robustness: search.html, compare.html and mvp-builder.html now degrade gracefully when data/ideas.json cannot load (file:// or offline) — the page index renders immediately and the tools show a serve-the-folder note instead of staying blank; search.html’s index gained the three pages it was missing (compare, legal checklist, about).
  • Nav: removed legal-checklist.html’s stray extra self-link so every page ships the same 11-link nav set.

27 Aug 2026

Hands-off bot runner script

Wrapper for manual and screen/tmux runs of the daily bot.

  • New: run-bot.sh — one-shot by default (./run-bot.sh); --loop reruns every 24 h with 15-minute retries after failures (3 strikes, then exit); --commit stages and pushes the five bot-managed files after each successful run; --log FILE picks the log path (default bot.log, now git-ignored).
  • Docs: README screen section points at the wrapper; repository table gains a row for it.
27 Aug 2026

Bot run docs tightened; write-safety fix in the update bot

Audit of the daily-update bot’s documentation and failure behaviour — stale claims removed, missing details added, one robustness fix.

  • Removed stale warning: the “one-line update needed for report 001b” note is obsolete — the committed .github/workflows/daily-update.yml already stages entry-simulator.html and ideas.html (byte-identical to docs/daily-update.yml, active on GitHub). The one-time activation section now says the workflow is already in place and only a fresh fork needs it copied.
  • README: the bot’s step list now includes the ideas.html counters/collision-watch pass; “Running the bot yourself” covers requirements (Python 3.9+, outbound HTTPS), exact failure semantics (abort-before-write on API failure, kept values on About-parse failure, unpatchedMarkers in stats.json), a screen/tmux recipe with logging, and a cons table comparing manual runs with the scheduled workflow.
  • Fixed: scripts/update_report.py now writes the CSV, both HTML patches and stats.json atomically (temp file + rename), so an interrupted run — Ctrl-C in a manual session, a killed CI job — can no longer leave a truncated file behind.

Launch kit, Level 0 document pack, and a responsive navigation layer

Three additions, none of which touch the audit data the bot owns.

  • New: launch/ — a shippable pay-to-rank board (board, outbid form with minimum-bid maths, free reference list from the inventory, browser-only owner console) plus launch/legal.html with the public terms, privacy notice, refund policy and paid-placement disclosure. Static, no backend; the paid board ships empty.
  • New: docs/level0-launch-pack/ — nine documents for a Level 0 launch (terms, privacy, refunds, ad-content policy with the 10-point screening checklist, disclosure spec, invoicing/books/tax, entity-bank-PG-trademark setup, ops SOP with a pre-launch gate, and the scope-lock guardrails), indexed in search.html.
  • Navigation: one shared responsive layer (assets/nav.css) loaded last in every page’s <head>, replacing per-page nav rules that disagreed with each other. Three tiers — full row above 1240px, scrollable pill rail 901–1240px, hamburger panel plus bottom quick-bar at or below 900px — with 44–46px targets, safe-area insets, dynamic-viewport panel heights, and scrim. site-enhancements.js now handles aria-expanded, Escape, tap-outside and close-on-link. The launch kit is added to every page’s top nav and quick-bar as Launch.
  • Unchanged: idea cards and verification verdicts stay hand-written; the bot still refreshes only the audit data hooks, the inventory CSV and the stats JSON.
